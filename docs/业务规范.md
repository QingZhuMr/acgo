# ACGO 业务规范

> 汇总后台核心业务规则：**操作日志、充值状态、货币双轨制、管理员权限**。
> 后端开发 / 写接口时必须遵循，防止行为混乱。

---

## 一、操作日志规范

### 1.1 统一入口
所有管理员操作日志通过 `app\common\AdminLog` 帮助类写入，确保 action 标准化：
```php
use app\common\AdminLog;
AdminLog::write(int $adminId, string $adminName, string $action, string $ip, string $remark = '');
```
- `remark` 写入 `admin_log.user_agent` 字段（截断 490 字符）。

### 1.2 预定义行为映射（`AdminLog::ACTION_MAP`）
| action | 中文显示 | 触发操作 |
|--------|---------|---------|
| `login` | 登录 | 管理员登录 |
| `logout` | 登出 | 管理员退出 |
| `kick` | 强制下线 | 管理员被强制下线 |
| `admin_create` | 新增管理员 | 后台新增管理员 |
| `admin_edit` | 编辑管理员 | 后台编辑管理员 |
| `admin_delete` | 删除管理员 | 后台删除管理员 |
| `admin_reset_pwd` | 重置管理员密码 | 管理员为他人重置密码 |
| `admin_ban` | 禁用管理员 | 禁用管理员 |
| `admin_unban` | 启用管理员 | 启用管理员 |
| `user_create` | 创建用户 | 后台创建用户 |
| `user_edit` | 编辑用户 | 后台编辑用户 |
| `user_ban` | 封禁用户 | 后台封禁用户 |
| `user_unban` | 解封用户 | 后台解封用户 |
| `user_delete` | 注销用户 | 后台注销用户 |
| `recharge` | 充值 | 人工充值 |
| `withdraw` | 提现 | 提现 |
| `system_setting` | 系统设置 | 修改系统设置 |

> **新增行为时**：先在 `ACTION_MAP` 加映射，再写日志。

### 1.3 写日志位置
| 控制器 | admin_log | user_log |
|--------|-----------|----------|
| `Login` | `login`/`logout` | - |
| `Admin` | `admin_*` | - |
| `User` | `user_*` | `change_password`（修改密码） |
| `Recharge` | `recharge` | `recharge`（充值） |

> **用户操作日志（user_log）只记录 充值、提现、修改密码 三类**，其余操作（注册/登录/上传头像/封禁/解封/注销等）一律不写 user_log，避免无谓的写入开销。
> `User::log()` 只写 `admin_log`；`Recharge::manualRecharge()` 同时写 `admin_log` 和 `user_log`。

### 1.4 备注规范
- **充值**：`给 {昵称} 充值 {币种中文} +{金额}（{备注}）`
- **创建/编辑用户**：`后台创建用户` / `后台编辑用户`
- **封禁/解封**：封禁原因 / `解封用户`
- **注销**：`管理员注销用户：{操作管理员}`
- **管理员管理**：`新增/编辑/删除管理员：{账号}`

### 1.5 日志展示
`Log` 控制器用 `AdminLog::text($action)` 将 action 转中文，可按行为筛选。

## 二、充值状态规范

### 2.1 状态枚举（`recharge.status`）
| 值 | 名称 | 说明 |
|----|------|------|
| `1` | 发起中 | 接口充值初始状态，尚未完成付款 |
| `2` | 核对中 | 已提交付款，等待核对到账 |
| `3` | 已完成 | 充值成功，金额已入账钱包；**人工充值直接为此状态** |
| `4` | 已取消 | 超时/取消/审核拒绝 |

**流转**：
```
发起中(1) ─付款完成→ 核对中(2) ─核对到账→ 已完成(3)
    │                            │
    └─超时/取消/审核拒绝────────→ 已取消(4)
```

### 2.2 来源与操作人
| 来源 | `source` | 初始状态 | 操作人类型 |
|------|----------|---------|-----------|
| 人工充值 | `manual` | `3`（已完成） | `admin`（管理员） |
| 接口充值 | `api` | `1`（发起中） | `system`（系统，operator_id=0，operator_name='系统'） |

### 2.3 关键规则
1. **钱包入账时机**：仅当状态变为 `3` 才增加用户余额，防止重复入账。
2. **幂等性**：接口回调按充值订单号（`id`）幂等，避免重复加款。
3. **写日志**：充值成功后必须写 `admin_log` 和 `user_log`（action=`recharge`）。

### 2.4 徽章对应
| 状态 | 徽章类 |
|------|--------|
| 发起中 | `badge-cyan` |
| 核对中 | `badge-warm` |
| 已完成 | `badge-green` |
| 已取消 | `badge-gray` |

### 2.5 控制器常量（`Recharge.php`）
```php
protected const STATUS_NAME = [1 => '发起中', 2 => '核对中', 3 => '已完成', 4 => '已取消'];
protected const STATUS_BADGE = [1 => 'badge-cyan', 2 => 'badge-warm', 3 => 'badge-green', 4 => 'badge-gray'];
```

### 2.6 货币双轨制
系统仅保留两种货币，**已取消通用货币类型（`config.currency_type` 配置项移除）**：

| 代码 | 中文名 | 符号 | 精度 | 说明 |
|------|--------|------|------|------|
| `cny` | 人民币 | `¥` | 2 位小数 | 现金 |
| `paw` | 熊爪 | `熊爪` | 整数 | 平台积分，充值数量必须为正整数（不允许小数） |

- 钱包表 `wallet` 字段：`balance_cny`（人民币余额）、`balance_paw`（熊爪余额）。
- 充值表 `recharge.currency` 取值：`cny` / `paw`（默认 `cny`）。
- 入账精度：人民币 `round(金额, 2)`；熊爪 `round(金额, 0)`，入账前校验必须为整数。
- 展示规则：人民币带 2 位小数，熊爪显示为整数。
- 未来为「双轨制」运行模式，两种货币的兑换、获取、消费规则后续按业务场景再定义。

## 三、管理员权限规范

### 3.1 管理员等级（`admin.level`）
| 值 | 名称 | 说明 |
|----|------|------|
| `1` | 普通管理员 | 基础操作权限 |
| `2` | 管理员 | 中级权限 |
| `9` | 超级管理员 | 最高权限（默认账号 `admin`） |

### 3.2 菜单权限
侧边栏菜单按 `menu.level` 过滤：`level` 值表示**达到该等级及以上**的管理员可见。
```
控制台(1)/用户管理(1)   → 所有管理员
系统管理(9)└菜单管理(9)/管理员管理(9) → 仅超级管理员
```

### 3.3 操作权限
| 功能 | 普通(1) | 管理员(2) | 超级管理员(9) |
|------|---------|-----------|----------------|
| 查看后台主页 | ✅ | ✅ | ✅ |
| 用户管理 | ✅ | ✅ | ✅ |
| 菜单管理 | ❌ | ❌ | ✅ |
| 管理员管理 | ❌ | ❌ | ✅ |
| 重置他人密码 | ❌ | ❌ | ✅ |

### 3.4 安全规则
- 超级管理员（level=9）不允许被删除。
- 管理员不能删除自己当前登录的账号。
- 注销用户、重置密码等敏感操作需输入当前管理员密码二次确认。

### 3.5 密码说明
密码使用 `password_hash`（bcrypt）单向加密，不可解密；忘记密码由超级管理员重置。

## 四、用户系统（前台）
- 前台用户表 `user`，独立于管理员表；注册/登录接口在 `api` 应用。
- 用户状态：`0` 注销 / `1` 正常 / `2` 封禁。
- 封禁/解封/注销由后台管理员操作。
