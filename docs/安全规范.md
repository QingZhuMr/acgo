# ACGO 安全规范（前后端交互）

> 汇总**客户端（acgopc/多端）与后端 api 应用**的全部交互安全规则。
> 写接口 / 写客户端请求时必须遵循，防止非授权访问与越权。

---

## 一、安全模型概述

采用**请求签名 + 设备密钥**双层体系，取代"客户端硬编码密钥"的弱方案：

| 层 | 机制 | 用途 | 校验位置 |
|----|------|------|---------|
| 签名层 | `API_SECRET` 参与 HMAC-SHA256 请求签名 | 防重放、防伪造、防非授权调用 | `app/api/middleware/ApiAuth.php` |
| 设备层 | `device_key`（每设备唯一） | 业务接口用户态鉴权，单设备在线 | 同上，查 `user_device` 表 |

**核心原则**：
- **密钥不直接传输**：`API_SECRET` 只参与签名（HMAC），客户端不传明文密钥。
- **请求带时间戳**：签名含时间戳，防重放（普通接口 ±300s，校时入口 `user/domain` ±600s），即使 secret 泄漏签名也有时效。
- **客户端校时**：客户端启动时调 `user/domain` 拿服务端权威 `server_time`，计算时钟偏移并应用到后续签名时间戳，解决设备时钟不准（尤其国外/时钟漂移）导致"签名已过期"。
- **每台设备一个 `device_key`**：登录时后端签发，可单独踢下线。
- **同一账号 + 同一平台只允许一个设备在线**。

## 二、请求签名机制（所有接口必须）

### 2.1 签名算法
```
signature = HMAC-SHA256(API_SECRET, "timestamp|path")
```
- `timestamp`：客户端 Unix 秒级时间戳（**已校时**：本地时间 + 时钟偏移）
- `path`：接口路径，如 `user/login`、`update/check`（小写，不含前后斜杠）

> **path 必须与后端一致**：后端用 `$request->pathinfo()`（不含前后斜杠、转小写）验签。
> 客户端 `sign()` 签名前必须对 path 规范化（去首尾斜杠 + 转小写），
> 而 URL 拼接 `AppConfig.api(path)` 仍保留带斜杠——两者互不影响。若客户端用带斜杠的 path 签名，必现"签名校验失败"。

### 2.2 请求头
所有接口必须携带：
| 请求头 | 说明 |
|--------|------|
| `X-Timestamp` | 客户端时间戳（秒） |
| `X-Signature` | HMAC-SHA256 签名 |
| `X-Device-Key` | 业务接口额外携带（设备级密钥） |

### 2.3 服务端校验流程（`ApiAuth`）
1. 校验 `X-Timestamp` 为合法整数
2. 校验时间戳在允许窗口内（否则 `401 签名已过期`）：
   - 普通接口：`±300 秒`
   - 校时入口 `user/domain`：`±600 秒`（此时客户端尚未校时，容忍更大偏差）
3. 用 `API_SECRET` 重新计算 `HMAC("timestamp|path")`（path 用 `pathinfo()` 去斜杠小写）
4. `hash_equals` 比对签名（否则 `401 签名校验失败`）
5. 业务接口再校验 `X-Device-Key`（查 `user_device`，无效/下线则 `401`）

### 2.4 时钟校准（解决设备时钟不准）
**Unix 时间戳与时区无关**（全球统一 UTC 秒）。真正的问题是**设备时钟被设错/漂移**，
尤其在国外或时钟不准的设备上，本地时间与服务端可能偏差很大，导致"签名已过期"。

解决：客户端启动时用服务端时间校准时钟偏移。
1. 客户端调 `user/domain`（公开接口，时间窗放宽到 ±600s），拿到 `server_time`（服务端权威时间）
2. 计算偏移：`clockOffset = server_time - 本地时间戳`
3. 之后所有签名请求的时间戳用 `本地时间 + clockOffset`（`AppConfig.nowTimestamp()`）
4. 这样校准后的时间戳接近服务端时间，普通接口 ±300s 严格校验即可通过

```dart
// acgopc/lib/main.dart —— 启动时校时
AppConfig.clockOffset = serverTime - (DateTime.now().millisecondsSinceEpoch ~/ 1000);
```

### 2.5 签名示例（客户端）
```dart
// acgopc/lib/api_client.dart
static String sign(String timestamp, String path) {
  // 关键：path 规范化去斜杠转小写，与服务端 pathinfo() 完全一致
  final normalized = path.trim().replaceAll(RegExp(r'^/+|/+$'), '').toLowerCase();
  final digest = Hmac(sha256, utf8.encode(AppConfig.apiSecret))
      .convert(utf8.encode('$timestamp|$normalized'))
      .toString();
  return digest;
}
// 时间戳用校准后的
final ts = AppConfig.nowTimestamp().toString();
```

### 2.6 服务端验签（PHP）
```php
$path = strtolower(trim((string) $request->pathinfo(), '/')); // 去斜杠小写
$expected = hash_hmac('sha256', "{$timestamp}|{$path}", $secret);
if (!hash_equals($expected, $signature)) {
    return json(['code' => 401, 'msg' => '签名校验失败']);
}
```

### 2.7 时间本地化规范（所有客户端：win/安卓/iOS/H5 通用）

**核心原则**：时间在**传输与存储**统一用 **Unix 时间戳（UTC 秒）**；**展示**用客户端本地时区，**上传**转服务器时间戳。**所有类型客户端必须实现同一套公共时间工具**，禁止在业务代码里各自拼接时区字符串。

#### 2.7.1 传输格式
- 所有接口的时间字段一律为 **Unix 秒级时间戳（int）**，与时区无关、全球一致。
- **禁止**后端返回 `date('Y-m-d H:i:s')` 这类携带服务器时区的格式化字符串。
- **禁止**客户端把本地时间字符串直接上传；一律先转 Unix 时间戳再提交。

#### 2.7.2 服务端 → 客户端（展示）：以客户端本地时间为准
服务器返回的时间戳是**绝对时刻**，客户端展示时必须转成**本地时区**：
- 例如：服务器（北京时间）返回订单 `create_time=1755266400`，东京客户端展示为**东京本地时间**（15:30），北京客户端展示为北京本地时间（14:30）。同一时间戳，各端各自本地化显示。

```dart
/// 展示：服务器时间戳 -> 客户端本地时区
/// ⚠️ 必须 isUtc: true 先把时间戳解释为 UTC 绝对时刻，再 toLocal() 转本地时区。
/// 若漏掉 isUtc:true，会把时间戳误当"本地时间"，东京/北京等非 UTC 时区将显示错误。
DateTime serverTsToLocal(int serverTs) =>
    DateTime.fromMillisecondsSinceEpoch(serverTs * 1000, isUtc: true).toLocal();

/// 展示：格式化为本地时区字符串，如 '2026-08-15 15:30:00'
String formatServerTime(int serverTs, {String pattern = 'yyyy-MM-dd HH:mm:ss'}) {
  final local = serverTsToLocal(serverTs);
  // 用 intl 或手写补零格式化（win/安卓/iOS/H5 复用同一实现）
  return '${local.year}-${local.month.toString().padLeft(2,'0')}-...';
}
```

> **验证**：同一时间戳，北京客户端显示 `14:30:00`，东京客户端显示 `15:30:00`——
> 因为 `isUtc:true` 后的 `toLocal()` 会按各设备系统时区换算。若错写成 `isUtc:false`，
> 则所有端都显示"时间戳按本地时区硬解释"的值，东京/北京显示会一致但都**错**。

#### 2.7.3 客户端 → 服务端（上传）：转服务器时间
用户选定的本地时间转成 **Unix 时间戳** 再上传，服务器存 UTC 秒，不关心用户时区：

```dart
/// 上传：本地时间 -> 服务器 Unix 时间戳（UTC 秒）
int localToServerTs(DateTime local) =>
    local.toUtc().millisecondsSinceEpoch ~/ 1000;
```

#### 2.7.4 当前服务器时间（生成时间戳时用）
生成"当前时间戳"（签名、上传"now"类字段）时，用校时后的时间：

```dart
/// 当前服务器时间戳（= 本地时间 + 时钟偏移，见 2.4 校时）
int nowServer() => AppConfig.nowTimestamp();
```

#### 2.7.5 延迟问题如何考虑
- **转换不引入误差**：Unix 时间戳是绝对时刻（UTC 秒），从服务器生成到客户端展示，`toLocal()` 只是换显示时区，时间点不变。
- **展示用本地时钟即可**：时间戳是全局唯一的绝对时刻，客户端直接用本地时钟换算即可，与延迟无关。
- **上传同理**：本地时间 `toUtc()` 转出的 UTC 秒正确，无论客户端在哪个时区、时钟快慢。
- **只有"生成当前时间戳"受时钟影响**：已由 2.4 校时解决（校时后 `nowServer()` 接近服务器时间）。
- **结论**：延迟只影响"数据新鲜度"，不影响时间戳语义；时间转换本身无时区/延迟误差。

#### 2.7.6 公共方法清单（`TimeUtil`，各端统一）
| 方法 | 用途 | 场景 |
|------|------|------|
| `serverTsToLocal(serverTs)` | 服务器时间戳 → 本地时区 `DateTime` | 展示前转换 |
| `formatServerTime(serverTs, {pattern})` | 服务器时间戳 → 本地时区字符串 | 列表/详情展示 |
| `localToServerTs(localDateTime)` | 本地时间 → 服务器 Unix 秒 | 上传用户选定的时间 |
| `nowLocalToServerTs()` | 当前本地时间 → 服务器 Unix 秒 | 上传"现在"类字段 |
| `nowServer()` | 当前服务器时间戳（校时后） | 生成当前时间戳 |
| `formatLocal(t, {pattern})` | 本地时间按 pattern 格式化 | 本地 UI 展示 |

#### 2.7.7 落地清单
| 项 | 做法 |
|----|------|
| 后端返回时间字段 | 一律 Unix 秒时间戳（int），禁止 `date('Y-m-d H:i:s')` |
| 客户端展示时间 | 统一 `serverTsToLocal()` / `formatServerTime()` |
| 客户端上传时间 | 统一 `localToServerTs()` / `nowLocalToServerTs()` 转 UTC 秒 |
| 生成"当前时间戳" | 统一 `nowServer()`（校时后） |
| 公共工具 | 各端实现同一份 `TimeUtil`（win/安卓/iOS/H5），禁止散落拼接 |

> 举例（订单场景）：订单时间存 `create_time`（Unix 秒）。东京用户看订单记录，后端返回同一时间戳，
> 客户端 `formatServerTime(create_time)` 显示东京本地时间；用户选定的时间上传走 `localToServerTs()` 转 UTC 秒，
> 后端再存时间戳。全程无"服务器时区"掺入，多端一致。

## 三、设备级密钥（device_key）

### 3.1 签发流程（登录时）
1. 客户端带 `platform` + `device_id`（设备 UUID）调用 `user/login`（带签名）
2. 后端验证账号密码后：
   - 生成 `device_key`（32 位）
   - upsert 到 `user_device` 表（唯一键 `user_id + platform + device_id`）
   - **同账号 + 同平台其他设备 `status=0`（踢下线）**
3. 返回 `device_key` 给客户端

### 3.2 客户端保存
- `device_id`：首次生成（UUID v4），持久化到文档目录，**永不改变**
- `device_key`：登录后保存到文档目录，退出登录清除（保留 device_id）

### 3.3 使用场景（业务接口）
- `update/check`（更新检查）

### 3.4 传递方式
- 请求头 `X-Device-Key`

### 3.5 校验逻辑
```php
$device = Db::name('user_device')
    ->where('device_key', $deviceKey)
    ->where('status', 1)
    ->find();
if (!$device) {
    return json(['code' => 401, 'msg' => '设备密钥无效或已下线']);
}
$request->deviceInfo = $device;
```

## 四、接口分类与校验要求

| 接口 | 是否需要签名 | 是否需要 device_key |
|------|:---:|:---:|
| `user/login` | ✅ | ❌（登录前无设备密钥） |
| `user/register` | ✅ | ❌（需图形验证码） |
| `user/domain` | ✅ | ❌ |
| `captcha/image` | ✅ | ❌（获取图形验证码） |
| `user/status` | ✅ | ✅（账号状态检查） |
| `user/profile` | ✅ | ✅（修改昵称） |
| `user/uploadAvatar` | ✅ | ✅（上传头像，multipart 字段 `avatar`） |
| `user/changePassword` | ✅ | ✅（修改密码） |
| `update/check` | ✅ | ✅ |
| 其他业务接口 | ✅ | ✅ |

**中间件 `ApiAuth::$publicActions`**：仅 `user/login`、`user/register`、`user/domain`、`captcha/image` 属于签名即可的公开接口；其余自动要求 `device_key`。

**登录方式（`user/login` 参数 `account`）**：
- `account` 支持**手机号**或 **UID**（数字 ID），服务端按 `phone` 或 `id` 匹配。
- 密码错误统一返回"账号或密码错误"（不区分账号是否存在，防枚举）。
- **已移除用户名/账号字段**：`user` 表无 `username`，登录标识为 `phone`（唯一）或 `id`。

**注册图形验证码（防机器人）**：
- 客户端生成唯一 `captcha_id`（UUID），调 `captcha/image` 获取验证码图片（base64 PNG）。
- 服务端 GD 生成 4 位验证码，存 `verify_code` 表（`captcha_id → code`，5 分钟有效，一次性）。
- `user/register` 必须携带 `captcha` + `captcha_id`，校验通过后才放行；错误/过期/已用均拒绝。
- 验证码大小写不敏感；失败后客户端应刷新验证码。

**个人中心接口（`user/profile` / `user/uploadAvatar` / `user/changePassword`）**：
- `user/profile`（POST `nickname`）：修改昵称。业务接口，需 `device_key`。昵称非空、最长 50 字符。
- `user/uploadAvatar`（multipart/form-data，文件字段 `avatar`）：上传头像。仅允许图片（jpg/png/gif/webp/bmp，≤5MB），保存到 `public/static/avatar/`，返回相对路径 `avatar`（如 `/static/avatar/u1_xxx.png`），客户端用 `AppConfig.resolveUrl` 拼完整 URL 展示。
- `user/changePassword`（POST `old_password`、`new_password`）：修改密码。校验旧密码正确，新密码≥6 位；成功后清空该用户全部 `device_key`（强制下线重新登录）。
- 客户端头像"本地缓存"同步：新头像 URL 带唯一时间戳（`u{uid}_{时间戳}_{随机}.png`），URL 不同则 `Image.network` 自动加载新图，无需手动清缓存。
- **头像上传体验（大厂标准，QQ 同款）**：编辑资料对话框头像居中 + 右下角相机图标 → 点击 `FilePicker` 选图 → 打开**自绘裁剪控件**（`_AvatarCropEditor`，纯 Flutter 跨平台含 Windows）：
  - 黑色背景 + **圆形蒙层**（孔内显示图片，外黑）
  - **鼠标滚轮缩放**（以圆心为锚点，0.3x~8x）
  - **鼠标拖拽平移**（自动限制不露出圆外空白）
  - 导出圆形内**最大内接正方形**，输出 512x512 PNG
  - 不用第三方裁剪库（`crop_image_pro` 不支持 Windows 鼠标滚轮缩放，已弃用）
  → 裁剪完成本地即时预览 → 点"保存"才上传。上传成功返回新 URL 并更新本地 user map 缓存，左侧导航头像同步。
  - 后端接口 `user/uploadAvatar` 返回的响应体前部可能带 PHP startup notice 的 HTML 杂质，客户端用 `ApiClient.safeJsonDecode`（先剥离 HTML、提取末尾 JSON 块）解析。

## 五、多端隔离与单设备在线

### 5.1 平台标识（platform）
| platform | 端 | 下载/推送 |
|----------|----|----------|
| `win` | Windows | 上传安装包直链 |
| `android` | Android | 上传安装包直链 |
| `ios` | iOS | 推送 App Store 地址 |
| `mac` | macOS | 推送 App Store 地址 |
| `h5` | H5 | 预留 |

- 不同平台 → 不同 `device_key`，**可同时在线**
- 同一平台 → 只允许一个设备在线

### 5.2 单设备在线实现（登录时）
```php
Db::name('user_device')
    ->where('user_id', $user['id'])
    ->where('platform', $platform)
    ->update(['status' => 0, 'update_time' => $now]);
```

## 六、数据库表：user_device

```sql
CREATE TABLE `user_device` (
  `id`              INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`         INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '用户ID',
  `platform`        VARCHAR(20)  NOT NULL DEFAULT '' COMMENT 'win/mac/ios/android/h5',
  `device_id`       VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '设备唯一标识(UUID)',
  `device_key`      VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '设备密钥(每设备唯一)',
  `login_token`     VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '本次登录token',
  `last_login_time` INT          NOT NULL DEFAULT 0,
  `last_login_ip`   VARCHAR(45)  NOT NULL DEFAULT '',
  `status`          TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '0下线 1在线',
  `online_status`   TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '长连接在线：0离线 1在线(Swoole维护)',
  `last_online_time` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '最后在线时间戳(Swoole维护)',
  `create_time`     INT UNSIGNED NOT NULL DEFAULT 0,
  `update_time`     INT UNSIGNED NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uniq_user_platform_device` (`user_id`, `platform`, `device_id`),
  KEY `idx_device_key` (`device_key`),
  KEY `idx_online` (`online_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户设备会话表';
```

### 6.3 在线状态（后台实时查看用户是否在线）
- 由 Swoole 长连接维护：认证成功 → `online_status=1` 并刷新 `last_online_time`；连接关闭/失效 → `online_status=0`。
- Swoole 周期性（`heartbeat_interval`）对存活连接刷新 `last_online_time`，保证"在线"状态准实时。
- 后台 `user/getList` 返回 `online` 字段：该用户**任一设备**长连接在线即 `1`，否则 `0`。用户列表展示"● 在线 / ○ 离线"。
- 建表 SQL：`sql/user_device.sql`（含 `online_status`、`last_online_time` 字段）。

**关联的 user 表补充字段**：
- `user.password_changed` 密码修改时间戳（检测后台改密，密码验证通过时更新）——已包含在 `sql/user.sql` 建表脚本。

## 七、账号状态管理（注销 / 封禁 / 异地登录）

### 7.1 用户状态（user.status）
| status | 含义 | 登录行为 |
|--------|------|---------|
| `1` | 正常 | 允许登录 |
| `2` | 封禁 | **允许登录**（返回 `banned: true`），后续限制操作 |
| `0` | 注销 | **拒绝登录**（`账号已注销`） |

> 封禁允许登录是设计决策：登录后仍可进入，但后续业务操作会被限制（未来实现）。

### 7.2 账号状态检查接口 `user/status`（自动登录时）
自动登录恢复会话后调用，确认账号状态，返回：
| 字段 | 说明 |
|------|------|
| `account_cancelled` | 是否注销（true → 强制下线） |
| `banned` / `ban_reason` | 是否封禁及原因 |
| `kicked` | 是否被踢下线 / 异地登录 |
| `password_changed` | 密码修改时间戳（检测后台改密） |
| `user` | 最新用户信息 |

**客户端自动登录流程**：
1. 读本地加密凭据（`SecureStorage`）
2. 调 `user/status` 确认账号状态
3. 注销/被踢/401 → 清除凭据 + 返回登录页
4. 正常 → 用服务端返回的最新用户信息更新，进入主界面

### 7.3 密码变更检测
- `user` 表 `password_changed` 字段记录密码修改时间戳
- 登录成功时更新为当前时间（作为本次会话基准）
- `user/status` 返回最新 `password_changed`
- 客户端比对会话基准，若变化说明后台已改密 → 提示重新登录

## 八、实时推送（WebSocket + Swoole）

### 8.1 架构
```
客户端(win/安卓/iOS/H5)  <--WebSocket 长连接(2346)-->  Swoole 常驻进程
admin/api 后台操作  --写 push_queue 表-->  Swoole 每秒轮询并主动推送
```

- **WebSocket 服务**：独立常驻进程（`ws/server.php`），运行于 **PHP CLI**，
  仅依赖 Swoole + PDO，共享 `acgo` 数据库做设备认证。**不加载 ThinkPHP 框架**。
- **推送触发**：admin/api 通过 `app\common\Pusher` 写入 `push_queue` 表，WS 服务每秒轮询推送。
  两端仅通过 MySQL 解耦协作，无需额外内网 HTTP 通道。
- **Windows 限制**：Swoole 在 Windows（swoole-cli）仅支持单进程，故只用一个 WebSocket worker。Linux 生产环境可多进程（见《后端搭建教程.md》）。
- **客户端类型**：`user_device.platform` 取值为 `win`/`android`/`ios`/`h5`（另有 `mac` 预留），推送按平台下发。

### 8.2 运行环境与 ws/wss 决定（**服务端决定**）

**WS/WSS 协议由服务端决定，客户端只读取、不自作主张。**

| `.env` 配置 | 值 | Swoole 监听 | 对外协议 | 客户端连接 |
|-------------|-----|------------|---------|-----------|
| `APP_ENV = true` | 开发环境 | `ws://0.0.0.0:2346`（直接暴露） | `ws` | `ws://ip:2346` 直连 |
| `APP_ENV = false` | 生产环境 | `ws://127.0.0.1:2346`（仅内网） | `wss`（Nginx 反向代理） | `wss://api域名/ws` |

- **生产 WSS 采用 Nginx 反向代理（官方推荐）**：Swoole 内部始终监听 `ws://`（生产绑定 `127.0.0.1` 仅内网），由 **Nginx 对外提供 `wss://`**。
  SSL 证书完全由 Nginx 管理（宝塔可一键申请/部署），Swoole 自身不配置证书。
- **服务端强制 wss**：生产环境 Nginx 只暴露 443 端口的 `wss://`，Swoole 的 ws 端口不对外，
  因此仅能发起 `ws://` 的客户端将无法连接——这正是"服务端强制 wss"的隔离效果。
- **多域名支持**：一套 Swoole 服务可被任意多个域名的 Nginx 站点反向代理（各站点各自配 SSL 证书，
  均代理到 `127.0.0.1:2346`），客户端连接的是各自 api 域名下的 `/ws` 路径。
- **客户端获取环境**：客户端启动时调公开接口 `user/domain`，拿到 `ws_url`（完整连接地址）等参数。
  `user/domain` 返回：
  ```json
  {
    "api_domain": "127.0.1.3",
    "app_env": "dev",           // dev=开发  prod=生产
    "ws_scheme": "ws",          // ws 或 wss（服务端决定）
    "ws_host": "127.0.1.3",     // 客户端可达地址（开发=api_domain，非 WS_HOST）
    "ws_port": 2346,
    "ws_url": "ws://127.0.1.3:2346"   // 客户端直接用此地址连接（生产为 wss://api域名/ws）
  }
  ```
- **⚠️ 客户端可连接地址必须是 api_domain（如 `127.0.1.3`）**，**绝不能返回 `WS_HOST`（`0.0.0.0`）**：
  `0.0.0.0` 只是服务端监听通配地址，客户端连它必然失败。`ws_host`/`ws_url` 一律用客户端可达的 api 域名/IP。
- 客户端配置 `lib/app_config.dart` 中 `wsBase` 为**运行时可变**变量，由 `_loadDomainConfig()` 写入服务端返回的 `ws_url`。

### 8.3 数据库：`push_queue` 表
| 字段 | 说明 |
|------|------|
| `user_id` | 目标用户ID（0=广播，当前必填） |
| `platform` | 目标平台（win/mac/ios/android/h5），空=不限制 |
| `device_id` | 目标设备ID，空=不限制 |
| `payload` | 推送消息体 JSON（含 `type` 字段） |
| `pushed` | 0待推 1已推（WS 消费后置1） |
| `create_time` | 入队时间 |

建表 SQL：`sql/push_queue.sql`。

### 8.4 连接认证（WS）
1. 客户端连接地址由 `user/domain` 返回的 `ws_url`（含 scheme，如 `ws://127.0.1.3:2346` 或 `wss://api域名/ws`）
2. 连接后发送：`{"type":"auth","device_key":"xxx"}`
3. 服务端查 `user_device` 表校验 `device_key` 有效且 `status=1`
4. 通过后建立 `user_id+platform+device_id -> connection` 映射；失败则断开
5. **认证成功后置在线**：更新 `user_device.online_status=1` + `last_online_time`（后台实时在线状态依据，见 6.3 节）；连接关闭/失效时置 `online_status=0`
6. 认证超时（10s）未完成即断开

### 8.5 客户端消息协议
| 方向 | type | 说明 |
|------|------|------|
| 客户端→服务端 | `auth` | 认证（携带 device_key） |
| 客户端→服务端 | `ping` | 保活探测（服务端回 `pong`，客户端每 25s 发一次） |
| 客户端→服务端 | `bye` | 主动断开 |
| 服务端→客户端 | `auth_result` | `{ok, msg}` 认证结果 |
| 服务端→客户端 | `pong` | 保活响应 |
| 服务端→客户端 | `force_logout` | `{reason, time}` 强制下线（封禁/注销/异地/改密） |
| 服务端→客户端 | `update` | `{update:{version,title,message,download_url,mandatory}}` 新版本 |

### 8.6 后端推送触发点（admin 控制器）
- `Update.php`：新增/编辑/上线版本时 → `Pusher::broadcastUpdate(platform, payload)` 推送该平台在线用户
- `User.php`：封禁/注销 → `Pusher::forceLogout(userId, platform, deviceId, reason)` 强制下线

### 8.7 客户端接入（`lib/ws_service.dart`，各端通用）
```dart
// 登录成功后启动
WsService.instance.start(
  onForceLogout: _handleWsForceLogout, // 收到 force_logout 清凭据回登录页
  onUpdate: _handleWsUpdate,           // 收到 update 用 Updater 弹更新通知
);
// 退出登录时停止
WsService.instance.stop();
```
- 断线自动重连（指数退避 1→30s，登录态有效时持续重连）
- 每 25s 发 `ping` 保持连接
- **状态同步唯一通道**：封禁/踢下线/注销/改密/更新等全部由 WS 主动推送，客户端无其他轮询兜底

#### 更新检查规则（`lib/updater.dart`）
- **自动检查**（启动/登录后 `showUpdateIfAvailable()`）：命中本地忽略列表（`ignored_versions.json`）的版本**不弹通知**。
- **手动检查**（设置页"检查更新"）：必须 `checkUpdate(ignoreFilter: false)`，**绕开本地忽略缓存**，始终以服务端最新版本为准，让用户能看到曾被忽略过的新版本。
- 手动检查拿到结果后直接用 `showUpdateIfAvailable(info)` 推送，避免二次 `checkUpdate()` 被忽略过滤。
- 手动检查的"正在检查更新…"提示用固定 id，完成后 `dismiss`，防止残留。

### 8.8 启动 / 停止（开发环境 Windows）
```bat
cd d:/webroot/acgo/ws
start.bat    # 启动（需 PHP74 CLI）
stop.bat     # 停止
```
> Linux 生产环境的启动与守护见《后端搭建教程.md》。

## 十、客户端行为标准（win / 安卓 / iOS，H5 除外）

### 10.1 WebSocket 断线重连 + 超时强制下线
- **重连**：WS 断线后自动重连，指数退避（1→2→4→…→30s 封顶），登录态有效时持续尝试。
- **重连总超时（行业标准）**：连续 **60 秒**无法重连成功，即视为离线，**强制下线回登录页**，提示"连接服务器超时，请重新登录"。
- 重连成功（认证成功）即重置计时；主动退出登录不触发重连。

### 10.2 记住密码 与 自动登录（两个独立功能，有联动）
登录页有两个勾选：**记住密码**、**自动登录**。

**联动规则**（自动登录依赖记住密码）：
- 勾选"自动登录" → **自动同时勾选"记住密码"**（自动登录的前置条件）
- 仅勾选"记住密码" → **不**自动登录，下次启动只自动填充账号密码，仍需手动点登录
- 取消勾选"记住密码" → **自动登录一并取消**（失去前置条件）

**行为**：
- 勾选"记住密码"：登录成功时加密保存账号+密码（`config/credentials.dat`，AES-256-CBC）。
- 勾选"自动登录"（必然同时记住密码）：下次启动**自动登录**（用记住的账号密码调登录接口），成功后直接进入主界面。
- 未勾选"记住密码"：登录成功不保存，且清除已保存的偏好（自动登录也随之失效）。

> 记住密码只负责"记住账号密码"；自动登录负责"下次自动进入"。二者由勾选联动，逻辑清晰。

### 10.3 缓存目录结构（行业标准）
应用数据根目录 `dataDir`（如 `Documents/acgo/`）按用途分子目录：
```
dataDir/
├── config/    # 用户偏好：credentials.dat(记住密码)、ignored_versions.json(忽略更新)
├── data/      # 设备数据：device_id(标识)、device_key(登录态)
└── logs/      # 日志（预留）
```
- `AppConfig.configDir` / `appDataDir` / `logsDir` 提供路径。
- 禁止在根目录平铺散落业务文件。

### 10.4 退出登录按需清除（不删所有数据）
退出登录（主动退出 / 被踢 / 封禁 / 注销 / WS 超时）时**按需清除**：
| 数据 | 退出登录时 |
|------|-----------|
| 登录态 device_key（`data/device_key`） | **清除** |
| 内存会话（当前 user / token） | **清除** |
| 设备标识 device_id（`data/device_id`） | **保留** |
| 记住的密码（`config/credentials.dat`） | **保留**（用户偏好） |
| 忽略的更新版本（`config/ignored_versions.json`） | **保留**（用户偏好） |

> 只有用户主动"清理本地数据"时才清空 config/data，普通退出登录不清用户偏好。

### 10.5 注册（win / 安卓 / iOS）
- 登录页提供"**去注册**"入口，跳转注册页。
- 注册页字段：昵称、手机号、密码、确认密码、**图形验证码**（点击图片可刷新）。**无用户名/账号字段**。
- **手机号是唯一登录标识**（`user.phone` 唯一），注册时手机号格式校验 `1[3-9]\d{9}`。
- **注册成功自动登录**，且以**保持登录**方式（即同时勾选"记住密码 + 自动登录"）。
- 注册/自动登录失败：提示原因、刷新验证码，留在注册页或回登录页手动处理。
- 验证码未正确获取/输入错误时不允许提交注册。

### 10.6 统一提示框规范（win / 安卓 / iOS / H5）
所有**非确认类**提示框（信息 / 成功 / 警告 / 更新）一律使用**通知卡片**（`NotifyStack`，宽 380、圆角 10、左侧色条），**禁止用 SnackBar** 等零散样式。确认类对话框统一走 `AppDialog.confirm()`。

**常用封装（`notify.dart`）**，调用时直接传参，禁止手写卡片样式：
- `NotifyStack.info(msg, {title})`：普通信息。**默认背景白天白 `#FFFFFF`、夜晚黑 `#23232A`**。
- `NotifyStack.success(msg, {title})`：成功，绿色调。
- `NotifyStack.warning(msg, {title})`：警告，黄色调。
- `NotifyStack.update(msg, {title, onDownload, onIgnore})`：更新，**红色调、常驻**。
- `NotifyStack.notify({...})`：最通用入口，可自定义 `backgroundColor`/`foregroundColor`/`titleColor`/`persistent`/`confirmOnDismiss` 等全部参数。
- `AppDialog.confirm(context, {title, message, confirmText, cancelText, danger})`：统一确认框，返回 `bool?`。

**默认色规则**：info 白天白、夜晚黑；success 绿、warning 黄、update 红。传 `backgroundColor`/`foregroundColor` 可覆盖默认色（如检查更新完成的绿色、提示更新的红色）。

**常驻通知点 X**：`persistent: true` 且 `confirmOnDismiss: true` 的常驻重要通知（如更新），点右上角 X 会先弹"是否忽略当前版本"确认框，确认后才忽略并关闭，防止误触。

## 十一、新增接口时必须遵守（Checklist）

- [ ] 判断接口类型：
  - 公开（登录/注册/域名）→ 加入 `ApiAuth::$publicActions`，仅需签名
  - 业务 → 不加入白名单，自动要求签名 + `device_key`
- [ ] 客户端请求走 `ApiClient`（统一签名 + 设备密钥头），不手写 http
- [ ] 签名只覆盖 `timestamp|path`，**不要**把 body 内容加入签名（POST 顺序会导致签名不一致）
- [ ] 禁止把 `API_SECRET` 明文传给请求头（只参与签名）
- [ ] 设备密钥一律通过 `DeviceService` 读取，不写死
- [ ] **时间字段**：后端返回一律 Unix 秒时间戳（int），客户端展示用 `TimeUtil.formatServerTime()`，上传用 `localToServerTs()`；禁止传/拼带时区字符串
- [ ] 客户端本地文件一律写入 `AppConfig.configDir`/`appDataDir`（按类型分目录），退出登录按 10.4 规则按需清除

## 十二、安全提醒

- **签名的本质**：`API_SECRET` 即使被逆向提取，攻击者也无法重放（时间戳过期）或伪造签名（需密钥）。这是对"客户端密钥可见"问题的务实解。
- **防刷登录**：签名防的是"非授权调用"，真正的**防撞库/防刷**还需在登录接口加**验证码 + 频率限制（IP/设备限流）**。
- **device_key 明文存储**：当前存文档目录明文文件，如需更高安全可对 device_key 加密存储（复用 `SecureStorage`）。
- **单设备在线的局限**：同平台互踢基于 `status` 标记，若需更强可在业务请求校验 `login_token` 与 `device_key` 双匹配。
