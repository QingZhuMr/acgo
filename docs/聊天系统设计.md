# ACGO 聊天系统设计（第二期）

> 本文档定义聊天系统的完整设计，供第二期实施。第一期已完成关注体系 + 好友列表
> （好友 = 互相关注，接口见 API接口文档.md 1.8）。

## 1. 整体架构

```
发送方客户端 ──E2EE 加密──> 服务器 ──密文──> 接收方客户端（解密）
                              │
                              └─ 30 天缓存期（离线消息自动清理）
```

- **端到端加密（E2EE）**：消息在发送方客户端加密为密文，服务器仅存储/转发密文，
  **服务器无法解密**。接收方客户端用私钥解密。
- **好友**：仅互相关注（`user_follow` 双向）才能聊天。
- **30 天缓存期**：消息密文在服务器保留；**接收方 30 天内未上线**，其服务器缓存消息
  被定时任务自动清理。已上线接收方消息由 WS 实时推送，服务器不留存（或按需短期留存）。

## 2. 密钥体系

### 2.1 密钥对
- 每个用户客户端生成 **X25519 密钥对**（现代椭圆曲线，配合 AES-256-GCM 混合加密）。
- **私钥**：仅存本地（Windows：SQLite + 可选系统凭据保护；未来 macOS：Keychain）。
  私钥**永不上传**。
- **公钥**：上传服务器（`user_e2ee_key` 表），用于他人向该用户发送加密消息。

### 2.2 混合加密流程（发送）
1. 生成随机临时密钥对（ephemeral keypair）
2. 用接收方公钥 + 临时私钥做 X25519 密钥协商 → 共享密钥
3. 共享密钥经 HKDF 派生 → AES-256-GCM 密钥
4. 用 AES-GCM 加密消息明文（带随机 nonce）
5. 发送内容：`{ ephemeral_pub, nonce, ciphertext }` + 消息元数据（明文）
6. 服务器仅存密文 + 元数据

### 2.3 解密流程（接收）
1. 用接收方私钥 + 消息的 ephemeral_pub 做 X25519 协商 → 同一共享密钥
2. HKDF 派生 AES 密钥 → AES-GCM 解密

### 2.4 密钥管理
- 用户首次登录消息功能时生成密钥对；本地 SecureStorage/SQLite 存私钥。
- 公钥上传；服务器 `user_e2ee_key.user_id` 唯一。
- 换设备：导入导出（见 §5）携带私钥。

## 3. 数据结构

### 3.1 服务器（MySQL）
```
user_e2ee_key     -- 用户公钥
  id, user_id, public_key(TEXT), status, create_time

chat_message      -- 聊天消息（密文，30 天缓存）
  id, chat_id(VARCHAR 双向会话id), sender_id, receiver_id,
  msg_type(TINYINT: 1文本 2图片 3文件 4系统),
  body(TEXT 密文), nonce(TEXT), ephemeral_pub(TEXT),
  client_msg_id(VARCHAR 客户端去重), status(TINYINT 1正常 2撤回 3删除),
  create_time, expire_time

chat_conversation -- 会话（可选，用于列表/未读数）
  id, chat_id, user_id, peer_id, last_msg_time, unread_count, ...
```

- `chat_id` = `min(sender,receiver)_max(sender,receiver)`（会话双向稳定）。
- **30 天清理**：定时任务删除 `expire_time < now` 的消息；或按用户 `last_online_time`
  距今 >30 天清理其未读密文。

### 3.2 客户端本地（SQLite，sqflite）
```
local_chat_message
  id(PK), chat_id, msg_id(服务端id), client_msg_id, sender_id, receiver_id,
  msg_type, plaintext(TEXT 解密后明文), ciphertext, nonce, ephemeral_pub,
  send_status(TINYINT: 0发送中 1已发送 2失败), create_time
local_key_store
  user_id(PK), private_key(TEXT), public_key(TEXT)
```

- 本地存**解密后的明文**（用户自己的设备可读），供离线浏览/搜索/导出。
- 多端不同步明文（E2EE），仅通过导出导入迁移。

## 4. 接口设计（第二期）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/chat/key` | GET/POST | 获取/上传本人公钥 |
| `/api/chat/keys` | POST | 批量获取好友公钥（发消息前） |
| `/api/chat/send` | POST | 发送消息（密文） |
| `/api/chat/history` | GET | 拉取某会话历史密文（分页，30天内） |
| `/api/chat/sync` | GET | 增量同步（时间戳 after） |
| `/api/chat/read` | POST | 标记已读（会话 + 消息id） |
| `/api/chat/recall` | POST | 撤回（期限内） |
| `/api/chat/clear` | POST | 清空某会话服务器缓存 |

**实时推送**：WS 新增消息类型 `chat_message`（密文透传）；客户端收到后本地解密。

## 5. 多端导出导入（第三期）

### 5.1 导出格式（JSON）
```json
{
  "format": "acgo_chat_export",
  "version": 1,
  "exported_at": "2026-08-18T12:00:00Z",
  "key": { "private_key": "base64...", "public_key": "base64..." },
  "conversations": [
    {
      "chat_id": "19_20",
      "peer": { "user_id": 20, "nickname": "张三" },
      "messages": [
        { "id": 1, "client_msg_id": "abc", "sender_id": 19,
          "msg_type": 1, "content": "你好", "create_time": 1700000000 }
      ]
    }
  ]
}
```

### 5.2 导入
- 校验 `format` + `version`
- 恢复私钥/公钥（覆盖本地）
- 合并会话消息（按 client_msg_id 去重）
- 导入后本地可离线浏览；新设备可用导入的私钥解密服务器缓存（30 天内）

### 5.3 安全
- 导出文件建议用户自备加密（如 zip 密码）——明文聊天记录导出风险由用户自担
- 导出内容含私钥，需明确警告

## 6. 安全与合规
- 服务器零知识：不存明文、不存私钥、公钥公开无碍
- 30 天缓存自动清理（定时任务，可配）
- 防滥用：好友才能发消息；频率限制；客户端消息去重（client_msg_id）
- 举报/审计：E2EE 下服务器无法审阅内容，配合本地举报（截图）兜底
