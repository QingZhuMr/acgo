# ACGO 聊天系统设计（大厂级规范）

> 本文档定义聊天系统的**完整规范**，参照正规大厂端到端加密聊天方案
> （Signal/WhatsApp 架构、微信/Telegram 体验）落地。实施顺序见 §7。

## 1. 总体架构

```
发送方 ──E2EE加密──> 服务器(密文,30天) ──WS推送──> 接收方(解密)
   │                    │
   └─本地SQLite明文──┘  └─定时清理过期密文
```

- **端到端加密**：服务器仅存密文 + 元数据，无法解密（零知识）。
- **好友**：仅互相关注可聊天。
- **30 天缓存**：接收方 30 天未上线 → 其离线密文被定时清理。

## 2. 密钥体系（大厂标准：X25519 + AES-GCM，长期密钥 + 会话密钥）

### 2.1 三层密钥模型
| 层 | 密钥 | 用途 | 存储 |
|----|------|------|------|
| 身份密钥 | 长期 X25519 密钥对（`IK`） | 标识用户身份 | 私钥本地加密，公钥服务器 |
| 签名密钥 | Ed25519 密钥对（`SK`） | 消息签名防篡改 | 私钥本地，公钥服务器 |
| 会话密钥 | 每条消息临时生成 X25519 密钥对（`EK`） | 密钥协商（PFS） | 仅内存，不落盘 |

### 2.2 混合加密（每条消息）
1. 生成临时 `EK` 密钥对（每消息一次 → **完美前向保密 PFS**）
2. X25519(临时私钥, 接收方身份公钥) → 共享密钥
3. HKDF-SHA256(共享密钥 + 临时公钥) → AES-256-GCM 密钥
4. AES-GCM(明文, 随机 nonce) → 密文
5. Ed25519 签名(消息哈希) → 防篡改
6. 发送内容：`{ ek_pub, nonce, ciphertext, signature }`

### 2.3 密钥管理
- 首次进聊天生成密钥对，私钥**本地 AES 加密后**存 SQLite（密码/系统钥匙串派生），公钥上传服务器。
- **密钥轮换**：定期（如 90 天）或检测到泄露时轮换；服务器 `user_e2ee_key` 支持多公钥版本（`key_id`），客户端发消息优先用对方最新公钥，解密按 `key_id` 找对应私钥。
- **多设备**：私钥随导出导入迁移（§6）；服务器按设备存公钥。

## 3. 数据模型

### 3.1 服务器（MySQL）
```
user_e2ee_key
  id, user_id, key_id(版本), public_key, sign_public_key, status, create_time
  UNIQUE(user_id, key_id)

chat_message
  id, chat_id, sender_id, receiver_id, msg_type(1文本 2图片 3表情 4系统),
  body(密文), nonce, ek_pub, signature, client_msg_id(幂等),
  seq(会话内序号), status(1正常 2撤回 3删除), create_time, expire_time
  UNIQUE(client_msg_id)   -- 幂等去重

chat_read    -- 已读回执
  id, chat_id, user_id, last_read_seq, update_time

chat_conversation  -- 会话（按需）
  id, chat_id, user_id, peer_id, last_msg_id, last_msg_time, unread_count, update_time
```

### 3.2 客户端本地（SQLite）
```
local_chat_message
  id(PK), chat_id, msg_id, client_msg_id(UNIQUE), sender_id, receiver_id,
  msg_type(1文本 2图片 3表情), seq, plaintext(明文), ciphertext, nonce, ek_pub, signature,
  send_status(0发送中 1已发送 2失败 3已读), create_time, delivered(是否送达)
  -- 另有 recalled(撤回), read_status(已读), image_local_path(图片本地缓存) 列

local_deleted_msg   -- 多选删除（仅本设备删除）防"复活"
  msg_id(PK), delete_time   -- 拉历史/断线同步按 msg_id 过滤，服务器缓存消息不会重新出现

local_conversation  -- 会话列表
  id(PK), chat_id(UNIQUE), peer_id, peer_nickname, peer_avatar,
  last_msg_text, last_msg_time, unread_count, update_time

local_key_store
  user_id(PK), key_id, private_key(加密), public_key, sign_private(加密), sign_public
```

### 3.3 消息体明文格式（E2EE 密文内自包含）

body 为 AES-GCM 加密后的**明文 JSON/纯文本**，按 `msg_type` 约定（接收方解密后按类型渲染）：

| msg_type | 明文格式 | 说明 |
|----------|----------|------|
| 1 文本 | 纯文本 | 引用消息为 JSON：`{"text":"实际文本","reply_to":{"id","nickname","msg_type","preview"}}`，非引用保持纯文本（向后兼容） |
| 2 图片 | `{"url":"/static/chat/xx.jpg"}` | 附件上传统一走 `/api/chat/upload` |
| 3 表情 | `{"url":"/static/sticker/xx.png","w":240,"h":240}` | 表情包直发，对端按 w/h 等比缩放（最长边 120px）；gif 支持动效；**气泡无包裹/圆角**透明直出、不可点击放大；右键「添加到表情」收藏（`POST /api/sticker/add` 按 url 软引用） |
| 4 系统 | 文本 | 预留 |

引用消息的 `reply_to` 含被引用消息的 `id`（服务器 msg_id）、`nickname`、`msg_type`、`preview`（内容预览），**随密文传递**，服务器不可见，对端直接渲染引用块（昵称 + 单行预览 + 点击跳转定位）。

## 4. 接口设计

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/chat/key` | GET/POST | 获取/上传公钥（含 key_id、签名公钥） |
| `/api/chat/keys` | POST | 批量获取用户公钥列表 |
| `/api/chat/send` | POST | 发送（密文+签名），client_msg_id 幂等 |
| `/api/chat/history` | GET | 游标分页拉历史（before_id） |
| `/api/chat/sync` | GET | **断线补偿**：按 seq/时间戳增量同步（`after_seq`） |
| `/api/chat/read` | POST | 标记已读（会话 seq） |
| `/api/chat/recall` | POST | 撤回（时限内） |
| `/api/chat/clear` | POST | 清空会话服务器缓存 |

**WS 推送类型**：`chat_message`（新消息）、`chat_read`（已读回执）、`chat_read_sync`（跨端已读同步：自己其他设备读了消息，清未读角标）、`chat_recall`（撤回）、`chat_clear`（清空会话）、`typing`（正在输入）

## 4.1 离线消息通知（客户端）

收到对方新消息且**当前没在查看该会话**时弹通知（应用内 NotifyStack + Windows Toast），点击跳转会话：
- 触发点统一在 `_storeIncoming` 解密入库（WS 实时与断线 `sync` 共用同一入口）
- `upsertMessage` 返回**是否新插入** → 只对首次落库的消息通知（天然去重，同一条不会因 WS+sync 双通道重复弹）
- 自己其他设备发出的消息不通知；会话昵称取本地会话缓存兜底
- 跳转实现：main.dart 注入 `ChatNotifier.onOpenChat` → 切消息 tab + `MessagePageState.openChatWithPeer(peerId)`

## 5. 可靠性兜底（大厂标准）

### 5.1 发送链路
1. **乐观更新**：本地立即展示（发送中）→ 后台异步发送
2. **幂等去重**：`client_msg_id` 全局唯一，服务器重复收到直接返回原消息；本地 UNIQUE 索引防重复落库
3. **自动重试**：发送失败进入**待重发队列**，指数退避（1s→2s→4s→8s→30s 封顶）自动重试；网络恢复/WS 重连后立即触发
4. **发送超时**：单次请求 10s 超时；超时入队重试
5. **手动重发**：UI 点击失败消息 → 立即重发

### 5.2 接收链路
1. **WS 实时**：在线收到即推送
2. **断线补偿**：WS 重连成功后，调 `/chat/sync` 按 `after_seq` 拉取断线期间漏掉的消息 → 解密落库 → 本地会话未读数+1
3. **进会话拉取**：打开会话时游标分页拉历史（上滑加载更早）
4. **去重**：本地 `client_msg_id`/`msg_id` UNIQUE，重复消息忽略

### 5.3 会话与未读
- 本地 `local_conversation` 维护最近会话列表 + 未读数
- 收到新消息：未读+1；打开会话：清零并上报已读
- 会话列表排序：按 `last_msg_time` 倒序
