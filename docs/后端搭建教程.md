# ACGO 后端搭建教程（Linux 生产环境）

> 面向 **Linux 服务器**（本文以宝塔面板 + CentOS/Ubuntu 为例）。
> 本项目是 ThinkPHP8 多应用（index/admin/api）+ Swoole 实时推送（独立进程）架构。
>
> **三端应用域名**（在 `.env` 的 `DOMAIN_INDEX / DOMAIN_ADMIN / DOMAIN_API` 配置）：
> - `index`：官网/入口
> - `admin`：后台管理
> - `api`：对外接口（客户端只访问它）

---

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| PHP | **8.0+**（推荐 8.1） | ThinkPHP8 要求 PHP 8.0+；Swoole 与框架共用 |
| MySQL | 5.7+ / 8.0 | 本项目用 MySQL |
| Nginx | 任意稳定版 | 提供 HTTP/HTTPS + WSS 反向代理 |
| Redis | 可选 | 当前未用到，预留 |
| Composer | 最新 | 拉取依赖 |
| 扩展 | `swoole`、`pdo_mysql`、`openssl`、`fileinfo`、`mbstring`、`pcntl`、`posix`、**`gd` + FreeType** | `swoole` 是 WebSocket 服务运行前提（宝塔软件商店可一键安装）；WSS 反向代理方案由 Nginx 处理 TLS，PHP 侧 openssl 非必需但建议开启；`gd`+FreeType 用于注册图形验证码生成；`pcntl`/`posix` 为 Swoole 进程管理所需 |
| 字体 | **dejavu-sans 等 TTF 字体** | 验证码用 `imagettftext` 画字，服务器需装 TTF 字体，否则验证码画不出字（见下方「验证码字体」） |

> **PHP 版本关键**：CLI 和 Web（FPM）必须同一套 PHP 8.0+。若宝塔装了多个 PHP，请务必让
> Nginx 站点和 `php` 命令行都指向同一个 PHP 版本（如 `/www/server/php/81/bin/php`）。

#### 验证码字体（必需，否则验证码无字）

代码会按候选路径探测字体：Windows 优先 `C:/Windows/Fonts/arial.ttf`，Linux 优先
`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`。宝塔 CentOS/Ubuntu 默认可能没装，安装：

```bash
# CentOS / 宝塔
yum install -y dejavu-fonts-common dejavu-sans-fonts
# Ubuntu / Debian
apt install -y fonts-dejavu-core
```

安装后确认字体文件存在：
```bash
ls -l /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf
```

## 二、开放端口

| 端口 | 用途 | 是否对外开放 |
|------|------|-------------|
| `80` | HTTP | 开（可被 CDN/强制 HTTPS 关闭） |
| `443` | HTTPS + **WSS 反向代理** | **必须开** |
| `2346` | Swoole WebSocket（内部 ws） | **生产环境不要对外**，仅 `127.0.0.1` 内网 |

> 生产环境 Swoole 监听 `127.0.0.1:2346`，由 Nginx 在 443 上对外提供 `wss://`。
> **不要在云安全组/防火墙放行 2346 端口**，否则等于绕过强制 wss。

## 三、部署步骤

### 3.1 上传代码 + 安装依赖
```bash
# 上传项目到 /www/wwwroot/acgo 后：
cd /www/wwwroot/acgo
composer install --no-dev --optimize-autoloader
# 然后配置 .env（见 3.2）
```

### 3.2 配置 .env（生产模板）

`.env` 已被 `.gitignore` 忽略，不会随代码上传，需在服务器上手动创建。项目根目录已内置生产模板 **`.env.production`**，直接使用：

```bash
cd /www/wwwroot/acgo
cp .env.production .env
vi .env   # 修改【必改】项：DB_NAME / DB_USER / DB_PASS、DOMAIN_API、CORS_ALLOW_ORIGIN
```

参考模板如下（与 `.env.production` 一致）：

```ini
APP_DEBUG = false                # 生产必须 false，关闭报错堆栈

DB_TYPE = mysql
DB_HOST = 127.0.0.1              # 宝塔同机数据库用本机
DB_NAME = acgo                   # 数据库名（与导入 SQL 的库一致）
DB_USER = acgo                   # 数据库账号
DB_PASS = 你的数据库密码          # 数据库密码
DB_PORT = 3306
DB_CHARSET = utf8mb4

DEFAULT_LANG = zh-cn

# 三个应用的域名（换成你的真实域名，客户端只访问 api）
DOMAIN_INDEX = www.yourdomain.com
DOMAIN_ADMIN = admin.yourdomain.com
DOMAIN_API   = api.yourdomain.com

# 跨域白名单（多个域名用英文逗号分隔，带协议）
CORS_ALLOW_ORIGIN = https://www.yourdomain.com,https://admin.yourdomain.com,https://api.yourdomain.com

# 客户端请求签名密钥：必须与客户端 lib/app_config.dart 的 apiSecret 保持一致！
# 改了服务器端密钥，客户端也要同步改并重新编译
API_SECRET = acgo_secret_2026_K9x!qZ

# 运行环境：false=生产（WebSocket 强制 wss://）
APP_ENV = false

# ==================== Swoole（ws/server.php 读取） ====================
# 生产环境监听 127.0.0.1，仅内网给 Nginx 反向代理
WS_HOST = 127.0.0.1
WS_PORT = 2346
# 连接认证超时（秒）
WS_AUTH_TIMEOUT = 10
# 服务端周期性清理失效连接间隔（秒）
WS_HEARTBEAT_INTERVAL = 30
# Swoole 内置心跳：超过该秒数无数据则断开（客户端 25s 发一次 ping，建议 90）
WS_HEARTBEAT_IDLE = 90
# worker 进程数（生产可调高，如 4；Windows swoole-cli 强制 1）
WS_WORKER_NUM = 1
```

> **注意**：
> - 域名绑定在 `config/app.php` 从 `.env` 读取，改成真实域名后**用 IP 直接访问会 404**，这是正常现象。
> - **单站点部署**：只部署了 api 站点时，`DOMAIN_API` 填真实域名即可，`DOMAIN_INDEX / DOMAIN_ADMIN` 保持占位（未部署的域名不会命中）。**不要**把它们改成 api 同域名，否则请求会路由到错误的应用。
> - `CORS_ALLOW_ORIGIN` 填**客户端实际来源域名**，通常只需 api 域名；调试期可临时放宽，上线收紧。
> - `API_SECRET` 测试期可先与客户端保持一致，正式上线再更换（两端一起改、客户端重新编译）。

### 3.3 导入数据库

在 MySQL 中创建数据库（库名与 `.env` 的 `DB_NAME` 一致），然后按**顺序**导入 `sql/` 下的建表脚本。导入顺序有依赖（user 先于 user_device / recharge）：

```bash
mysql -u root -p acgo < sql/init.sql          # 后台 admin + admin_log
mysql -u root -p acgo < sql/user.sql          # 用户 user/user_log/wallet/config
mysql -u root -p acgo < sql/user_device.sql   # 设备会话表（依赖 user）
mysql -u root -p acgo < sql/verify_code.sql   # 图形验证码记录表
mysql -u root -p acgo < sql/post.sql          # 广场 post/评论/举报/点赞/收藏/敏感词
mysql -u root -p acgo < sql/sticker.sql       # 表情包表
mysql -u root -p acgo < sql/notification.sql  # 回复通知表
mysql -u root -p acgo < sql/push_queue.sql    # WS 推送队列表
mysql -u root -p acgo < sql/recharge.sql      # 充值记录表
mysql -u root -p acgo < sql/update.sql        # 客户端版本更新表
mysql -u root -p acgo < sql/menu.sql          # 后台菜单表
```

> `sql/seed_test_data.sql` 是本地测试数据（会清空用户并插入测试账号），**生产环境不要执行**。
> `sql/` 目录只保留 `.sql` 建表脚本，无需上传其他文件。

### 3.4 目录权限（可写）

宝塔默认站点用户 `www:www`，以下目录必须可写（ThinkPHP 缓存 + 图片上传）：

```bash
chown -R www:www /www/wwwroot/acgo/runtime
chown -R www:www /www/wwwroot/acgo/public/static
```

上传目录对应关系：
- `public/static/avatar/`  — 用户头像
- `public/static/post/`    — 帖子图片
- `public/static/comment/` — 评论图片
- `public/static/sticker/` — 表情包

### 3.5 配置 Nginx 站点（api 应用必须开 WSS 反向代理）
在宝塔「网站」中，为 `api` 域名创建站点，根目录指向 `public/`，并添加伪静态（ThinkPHP 规则）。
然后在 `api` 站点的 **配置文件** 中追加 WSS 反向代理：

```nginx
# 追加到 api 站点 server{} 内
location /ws {
    proxy_pass http://127.0.0.1:2346;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

> 这样客户端用 `wss://api域名/ws` 即可连接 Swoole。
> **多域名**：index/admin/api 各自站点都可加同样的 `location /ws`（只需在对外开放的 api 站点加），
> 指向同一个 `127.0.0.1:2346`。WSS 证书各站点独立配置。

## 四、WSS 证书说明（重点）

### 4.1 WSS 用的是 SSL 证书吗？
**是的。** WSS = WebSocket + SSL/TLS，使用的证书与 HTTPS **完全同一种**（X.509 证书，含 `.pem/.crt` + `.key`）。
WSS 与 HTTPS 共用 443 端口、同一套证书。

### 4.2 证书是否自动填？
- **生产环境证书由 Nginx 管理，与 Swoole 无关。** 因此**不写在 `.env` 里**，也不需要自动填到后端配置。
- 宝塔面板：「网站 → 你的 api 站点 → SSL」可 **一键申请 Let's Encrypt 免费证书**（自动续期），
  或部署自己购买的证书（阿里云/腾讯云 SSL、DigiCert 等）。
- 申请/部署后宝塔自动填入 Nginx 配置，无需手动改代码。

### 4.3 多域名如何配置证书？
本项目有 index/admin/api 三个域名。**证书与域名一一绑定**：
- 每个域名在宝塔各自站点下单独申请/部署 SSL 证书。
- 只需要给 **客户端会访问的域名**（api）配置 SSL 即可让 WSS 工作；
  admin/index 是否配 SSL 按是否对外 HTTPS 需求决定。
- 若用泛域名证书（`*.yourdomain.com`），一个证书可覆盖所有子域名，宝塔同样可管理。

### 4.4 证书在 `.env` 里怎么填？
**不需要填。** 我们采用官方推荐的「Nginx 反向代理 WSS」方案，Swoole 内部始终用 `ws://127.0.0.1:2346`，
TLS 终止由 Nginx 完成。因此 `.env` 中 **没有** `WS_SSL_CERT` / `WS_SSL_KEY` 配置项。

## 五、Swoole 进程管理（生产守护）

### 5.1 Linux 启动脚本
项目已内置 `/www/wwwroot/acgo/ws/start.sh`（按宝塔 **PHP 8.3** 配置，服务器版本不同改脚本里的 `PHP_BIN`）。参考内容如下：

```bash
#!/bin/bash
# ACGO 实时推送服务启动脚本（Linux 生产）
# 使用与 Web 一致的 PHP 版本，指向 ws/server.php
PHP_BIN=/www/server/php/83/bin/php
WS_DIR=/www/wwwroot/acgo/ws
LOG_DIR=$WS_DIR/logs

mkdir -p "$LOG_DIR"
cd "$WS_DIR"

case "$1" in
  start)
    nohup "$PHP_BIN" server.php start -d \
      >> "$LOG_DIR/ws.log" 2>&1 &
    echo "ACGO-WS started (PID $!)"
    ;;
  stop)
    "$PHP_BIN" server.php stop
    echo "ACGO-WS stopped"
    ;;
  restart)
    "$PHP_BIN" server.php restart
    echo "ACGO-WS restarted"
    ;;
  status)
    "$PHP_BIN" server.php status
    ;;
  *)
    echo "Usage: $0 {start|stop|restart|status}"
    exit 1
    ;;
esac
```

### 5.2 一键部署（推荐）

项目已内置 `ws/setup.sh`，一条命令自动完成：环境检查 → 启动 WS 服务 → 设置计划任务守护 + 开机自启：

```bash
cd /www/wwwroot/acgo/ws
chmod +x setup.sh
sudo ./setup.sh       # 普通用户执行前有 sudo 就加，root 直接跑
```

手动执行（等价步骤）：

```bash
chmod +x /www/wwwroot/acgo/ws/start.sh
/www/wwwroot/acgo/ws/start.sh start
/www/wwwroot/acgo/ws/start.sh status
```

### 5.3 开机自启（守护）
> Swoole 的 `-d` 守护模式在 Linux 下可靠。若需更强的进程守护（自动拉起），推荐 **Supervisor**。

**方案 A：Supervisor（推荐，自动拉起）**
```ini
# /etc/supervisord.d/acgo-ws.ini
[program:acgo-ws]
directory=/www/wwwroot/acgo/ws
command=/www/server/php/83/bin/php server.php start
user=www
autostart=true
autorestart=true
startretries=3
redirect_stderr=true
stdout_logfile=/www/wwwroot/acgo/ws/logs/supervisor.log
```
```bash
supervisorctl reread
supervisorctl update
supervisorctl start acgo-ws
```

**方案 B：宝塔计划任务（开机/每分钟自检）**
在宝塔「计划任务」新增 shell 任务，脚本：
```bash
if ! pgrep -f "server.php start" > /dev/null; then
  /www/wwwroot/acgo/ws/start.sh start
fi
```
执行周期：每分钟或开机执行。

## 七、多进程（可选，Linux 下 Swoole 支持）

生产 Linux 环境 Swoole 支持多进程。若需要更高并发，把 `.env` 的 `WS_WORKER_NUM` 调高（如 `4`）。
多进程时连接映射存放在 **`Swoole\Table`**（内存共享表，跨 worker 可见），因此推送/在线状态在
多进程下天然一致；跨进程推送依靠数据库 `push_queue` 表轮询，各进程各自轮询不会重复，
因置 `pushed=1` 后不再取。**Windows 开发环境（swoole-cli）必须保持 1**。
